## 2. What the project is

Tourne'Suite is Linux-level customizing for Windows with no phoning home. It replaces StartAllBack, YASB, Windhawk mods and similar tools with Tourne's own code. It has two halves:

- **The Windhawk suite** (`builds/tourne-suite-bN.wh.cpp`, the latest is b53). One Windhawk mod made of many parts. It holds the parts that have to run inside Explorer and other programs: Explorer Style (with explorer-layout), Explorer Colours, Theme Gaps, Classic Menus, System Text Color, Menu No Icons, Menu No Duplicates, Icon Redirect and Tweaks. It is built by `Build-TourneSuiteRedirect.ps1` from the part sources and `suite-redirect.template.cpp`.
- **Tourne Desktop** (`desktop/`). One 64-bit program holding the parts that need no hooks: the taskbar (`taskbar-host.cpp`), the switcher with tiling and borders (`switcher-host.cpp`), and system icons with flyouts (`system-icons-host.cpp`). Each is compiled in unchanged behind a Windhawk-shaped shim (`desktop/host/module-shim.inl`). Around them: Tourne Studio (every setting in one window), glass, the Tourne theme, motion, identity packs, a CSS injector for web-based apps, plugins, and shell mode.

Since 2026-10-05, Tourne Desktop runs on Tourne's PC **as the Windows shell**. A `--shell` watchdog starts a `--shell-child`, and Explorer stays hidden underneath so Windows apps still work. Tourne Desktop hosts the tray itself (`desktop/host/tray-host.cpp`).

The goal Tourne keeps coming back to is one running application for the whole look. Section 5 explains why that isn't fully possible now.

## 5. The hooks question (read this before suggesting anything about Windhawk)

Tourne asked to move off Windhawk entirely, because the point of the project is one running application. The parts that change how Explorer and other programs draw only work by running inside those programs, and Windhawk is what does that today.

- A plan for Tourne Desktop to do it itself was written (`research/plans/tourne-hooks-proposal.md`). Claude Code started building it, was stopped by its safety system, and will not build it, with or without exclusion lists. The plan is marked **not going ahead**.
- A later attempt to let the Studio write b53's settings into Windhawk was also stopped: it would have widened the permissions on Windhawk's settings key under HKLM. A read-only Studio page for b53's settings was started and stopped too.
- **So the current arrangement stands.** Tourne Desktop draws the shell (taskbar, tray, clock, switcher, flyouts, tray folders, Studio). Windhawk runs b53 with only the hook parts on. Tourne changes those parts' settings in Windhawk's own UI, or switches whole parts with `Set-SuiteParts.ps1` (as administrator).
- Tourne knows this and is disappointed about using two tools. Be straight about it if it comes up again.

## 6. Features that exist but Tourne hasn't tried yet

- **Tray folders by hand** (4099eb0, `system-icons-host.cpp`), in the hidden icons flyout:
  - Drop an icon on a folder tile to put it in.
  - Drop it on the open folder's name, or anywhere above its icons, to take it out.
  - Drop it on the middle half of another icon to make a new folder of the two. A name box opens over the title: Enter or a click away keeps the name, Escape keeps "New folder".
  - Right-click a folder tile, or the open folder's name: Rename, Glyph, Delete. Delete puts its hand-placed icons back loose.
  - The flyout's own right-click menu has "Folders as in the settings", which forgets the hand-made layout.
  - Storage: `HKCU\Software\TourneTray\TrayFolders` (REG_MULTI_SZ: `v1`, then `folder:name<TAB>glyph`, `match:pattern`, `pin:file.exe`, `loose:file.exe`). Pins and loose win over patterns. Same-named folders merge, and repeated patterns are dropped. That tidied Tourne's b53 list, where folders 4 and 5 shared a name and folder 4 repeated folder 2's patterns.
- **AlienFan's tooltip** (1807619): alienfan-gui sets its tip only when told of the pointer. The overflow flyout now posts WM_MOUSEMOVE to an icon's owner on hover (`HoverHiddenIcon` in `tray-shared.cpp`), and reads the tooltips again 250 ms later.

## 8. How to build, test and swap

- **Build Tourne Desktop:** `.\desktop\Build-TourneDesktop.ps1`. It uses Windhawk's own clang (`C:\Program Files\Windhawk\Compiler`) targeting x86_64. The output is `desktop\build\TourneDesktop.exe` plus `TourneDesktop.symbols.exe`. Luau is compiled once by `desktop\Build-Luau.ps1` and kept.
- **Swap a build into the running shell:** `.\desktop\Swap-TourneDesktop.ps1 -Commit <hash>` (add `-DryRun` to see the steps). It ends only the shell child with exit code 3, a planned restart that doesn't count as a crash. **Never** quit the shell copy with exit code 0: that hands the session to Explorer.
- **Plugin tests:** `.\tools\plugins\Run-PluginTest.ps1 <ids>`. Options are `-Sandbox` and `-Settings`, and environment variables `TOURNE_PLUGINRUN_MS`, `_CLICK`, `_SHOT`, `_SHOT2` and `_PANELCLICK` drive clicks and panel pictures.
- **Tray probe:** `tools/tray/trayprobe.cpp` lists the shell-mode tray's icons with program, id, NOTIFYICON version and tooltip. Its build line is at the top of the file.
- **Windhawk suite build:** `.\Build-TourneSuiteRedirect.ps1`. It takes the next build number from `build-number.txt` (it says 52, though b53 exists) and writes `builds\tourne-suite-bN.wh.cpp`. Settings come from the enabled suite build in Windhawk.
- **Suite parts on or off:** `.\tools\windhawk\Set-SuiteParts.ps1 -Off <part>` / `-On <part>` / `-HooksOnly` (administrator). Then turn the mod off and on in Windhawk if it doesn't pick the change up.
- **Import a suite build's settings:** `TourneDesktop.exe --import b53`, or the tray menu item "Import my Windhawk suite settings". It overwrites the imported keys in `tourne-gui.conf` and keeps a `.before-import` copy.

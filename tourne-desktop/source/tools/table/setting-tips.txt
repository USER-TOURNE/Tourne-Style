# Tourne'Table: the hover tips in the quick-settings panel, one per setting.
# key = what it is and where on screen it shows | Try: a value to start from, and the look it gives. A \n starts
# a new line in the tip: a choice gets one line per option, saying what that option does.
# make-settings-table.py reads this into the settings table. A setting without a line here shows its
# settings-page description instead. Plain words, no jargon; keep each under about 50 words.

appearance.shape = The kind of picture the visualizer draws. Changes the whole visualizer.\nStereo: bars growing up from a line.\nMountain: the bars joined into one filled ridge.\nMirror: bars growing both ways from a centre line.\nWave: a smooth curve through the bar tops.\nBreathe: one soft shape that swells with the level.\nDots: a dot at each bar's top instead of a bar.\nRadial: bars around a circle.\nOscilloscope: the sound's actual waveform as a line, like a lab scope.\nGoniometer: a stereo cloud showing how wide the mix is.\nTerminal: the spectrum drawn in text characters.\nLED Meter: segmented bars, green, amber, red.\nLine Spectrum: a filled curve with a glowing edge.\nPolar Bloom: Radial drawn as one filled flower.\nSpectrogram: a scrolling colour history of the spectrum.\nVU Needles: two analog meters, left and right.\nStereo Field: left channel above the line, right below.\nParticles: bars plus sparks that fly off on each beat. | Try: Oscilloscope for a thin glowing wave, Stereo for classic bars, Particles for a lively beat-driven look.
appearance.reflection = A faded mirror image of the bars on a floor under them. Shows below the visualizer, only with bars that grow up from the bottom. | Try: 40 for a glossy floor, 100 for a full reflection.
appearance.fxGlow = A soft light around every bar, dot or line. Makes the visualizer itself glow. | Try: 30 for a neon look, 5 for a faint edge glow.
appearance.fxGlowRadius = How far the glow reaches out from each bar. Only matters with Glow above 0. | Try: 3 for a tight halo, 12 for a hazy one.
appearance.fxBloom = Light bleeding out of the whole picture, like a camera lens catching something bright. Spreads past the bars onto the panel. | Try: 15 for a dreamy shine, 50 for a strong blown-out look.
appearance.fxBloomRadius = How far the bloom light spreads. Only matters with Bloom above 0. | Try: 4 for a close shine, 24 for a wide wash.
appearance.fxOutlineWidth = A thin line just inside each bar's edge. Bars keep their size. | Try: 1 with a white Outline Color for crisp, drawn-looking bars.
appearance.fxOutlineColor = The colour of the bar outline. Only shows with Outline Width above 0. | Try: #B0FFFFFF for a soft white edge.
appearance.fxShadow = A drop shadow behind every bar, dot and line, falling on the panel or wallpaper. | Try: 50 to lift the bars off a busy wallpaper.
appearance.fxShadowColor = The shadow's colour. | Try: #000000 for a normal shadow, your accent colour for a coloured echo.
appearance.fxShadowX = How far the shadow sits to the right of the bars (negative is left). | Try: 2 for a subtle offset, 0 for a shadow straight below.
appearance.fxShadowY = How far the shadow sits below the bars (negative is above). | Try: 3 for a light-from-above look.
appearance.fxShadowSoftness = How blurry the shadow's edge is. 0 is a hard, flat shadow. | Try: 0 for a retro pixel shadow, 6 for a soft one.
appearance.barHollow = Draws bars as outlines with the inside left see-through. | Try: On with Hollow Line Width 1.5 for a wireframe look.
appearance.barHollowWidth = How thick the outline of a hollow bar is. Only with Hollow Bars on. | Try: 1 for hairlines, 3 for bold outlines.
appearance.barDash = Cuts every bar into dashes along its length, like an LED segment meter. 0 keeps bars solid. | Try: 2 with Dash Gap 1 for a dotted meter look.
appearance.barDashGap = The space between the dashes. Only with Dash Length above 0. | Try: 1 for tight segments, 3 for open ones.
appearance.barTilt = Leans every bar sideways from its base, like italic text. | Try: 15 for a sense of speed, -15 to lean the other way.
appearance.barMirrorGap = With Anchor set to Middle, pulls the top and bottom halves of the bars apart, leaving a spine. | Try: 2 for a thin centre line through the bars.
appearance.afterimage = A see-through trail behind each bar that jumps up with it and sinks back slowly. | Try: 25 for a ghostly echo of every hit.
appearance.afterimageLength = How many seconds the afterimage trail takes to sink away. Only with Afterimage above 0. | Try: 1.75 for a slow fade, 0.5 for a quick flicker.
appearance.orientation = Which way the visualizer runs.\nHorizontal: bars side by side across the screen, growing up (or down).\nVertical: bars stacked down the screen, growing sideways, to stand along a screen edge. | Try: Vertical beside a window or along the side of the screen.
appearance.barCount = How many bars are drawn across the visualizer. More bars means more detail and thinner spacing. | Try: 32 for chunky bars, 135 for a fine, detailed spectrum.
appearance.barWidth = How thick each bar is, in pixels. | Try: 2 for a fine line look, 8 for bold blocks.
appearance.barGap = The space between bars, in pixels. | Try: 1 for a near-solid wall, 4 for clearly separate bars.
appearance.barMaxSize = How tall a bar can get at full volume, in pixels. Sets the visualizer's height. | Try: 18 for a slim strip, 140 for a tall display.
appearance.barIdleSize = The height bars keep when nothing is playing, so it never goes fully flat. -1 hides them. | Try: 2 for a resting line, -1 to vanish in silence.
appearance.barCornerRadius = How round the bar corners are. One number for all, or four for each corner. | Try: 0 for square pixel bars, 3 for soft pills.
appearance.colorMode = Where the bar colours come from.\nSolid: every bar in Color.\nGradient: a fade from Gradient Color 1 on the left to 2 on the right.\nReactive Gradient: each bar picks between the two by how loud it is (quiet = 1, loud = 2).\nWindows Accent Color: your Windows accent colour.\nAlbum Art Color: the main colour of the playing song's cover.\nDynamic Album Gradient: a gradient made from the cover's colours.\nAcrylic: see-through frosted bars tinted with Color.\nRainbow Cycle: colours that keep cycling (speed below).\nTourne: the Tourne teal-to-red fade. | Try: Reactive Gradient so loud hits change colour, Album Art Color to match each song.
appearance.color = The bar colour when Color Mode is Solid (and the tint for Acrylic). | Try: your palette red #E57474, or #15FFA2 for neon green.
appearance.gradientColor1 = The first colour of the gradient (left, or the quiet end for Reactive Gradient). | Try: #4CE38D for a green-to-red Tourne fade.
appearance.gradientColor2 = The second colour of the gradient (right, or the loud end for Reactive Gradient). | Try: #A95D5D to end the fade in a muted red.
appearance.sensitivity = How strongly the bars react to sound. Higher fills the bars with quieter music. | Try: 100 for a calm look, 200 if bars barely move.
appearance.sensitivityCurve = What happens when a loud sound would push a bar past the top.\nExponential (Soft): squeezes early and smoothly; loud parts look gentle and nothing slams the ceiling, but big hits look smaller.\nKnee (Balanced): leaves quiet and medium levels exactly as they are and only squeezes the loudest part; the usual choice.\nPower (Headroom): squeezes least and latest, so hits stay punchy and bars reach the top more often. | Try: Knee for most music, Power for punchy electronic, Exponential for calm, smooth motion.
appearance.inputGain = A fixed volume boost or cut on the sound before the visualizer reads it, in dB. | Try: 3 if your player volume is low, -3 if everything maxes out.
appearance.autoGain = Lifts quiet sources automatically so they still fill the bars. Loud music is unchanged. | Try: On if you switch between quiet podcasts and loud music.
appearance.autoGainMaxBoost = The most Auto Gain is allowed to lift a quiet sound, in dB. | Try: 9 for gentle help, 18 for very quiet sources.
appearance.smoothing = Makes bars rise and fall more slowly for a steadier, calmer motion. | Try: 0 for snappy, 6 for smooth and easy to watch.
appearance.eqPreset = Boosts parts of the sound before it's drawn, to suit a music style.\nDefault: no change.\nBass: lifts the low end, for hip-hop and EDM.\nRock: lifts lows and highs a little, mids flat.\nPop: lifts vocals and mids.\nJazz: gentle lift to mids and highs.\nElectronic: lifts sub-bass and treble. | Try: Default for an honest view, Bass if your music is bass-heavy but the left bars look flat.
appearance.fftSize = How finely the sound is split into pitches before it becomes bars.\n1024: fastest reaction, least detail (bass bars blur together).\n2048: the balance; the sweet spot with the Precision engine.\n4096: more detail in the bass, a touch slower.\n8192: the most detail, slightly laggier and more CPU. | Try: 2048 for most setups, 8192 for many thin bars on a big screen.
appearance.freqScale = How bars are spread from low to high pitch.\nLog: each octave gets equal room, like a piano; the natural look.\nLinear: equal Hz per bar; bass squashed into a few bars on the left, treble takes most of the width.\nMel: spaced like the pitches we hear as evenly spaced.\nBark: spaced like the ear's critical bands; more room for the mids.\nERB: spaced like the ear's own filters; a balanced, ear-like spread. | Try: Log for music, ERB for an evenly busy spectrum.
appearance.peakFreqEnabled = Shows a small number with the strongest pitch right now (or loudness, see Readout Content), near the bars. | Try: On with the Terminal font for a studio meter look.
appearance.peakFreqAlignH = Where the readout sits from left to right.\nLeft, Center or Right of the visualizer. | Try: Right to keep it clear of the bass on the left.
appearance.peakFreqAlignV = Where the readout sits from top to bottom.\nAbove: outside, over the visualizer.\nTop: inside, along the top.\nMiddle: inside, centred.\nBottom: inside, along the bottom.\nBelow: outside, under the visualizer. | Try: Above for a clean label that never covers the bars.
appearance.oscilloscopeMultibandEnabled = Colours the Oscilloscope line by which part of the sound is strongest: low, mid or high. | Try: On for a scope that changes colour with the music.
appearance.oscilloscopeWindowMs = How much time the Oscilloscope line shows end to end. Short looks like a lab scope, long like a rolling wave. | Try: 24 for sharp wave cycles, 175 for a smooth ribbon.
appearance.oscilloscopeDamping = Slows how fast the Oscilloscope line changes shape so it is easier to follow. | Try: 0 for raw and jittery, 80 for a slow, flowing line.
appearance.verticalAnchor = Where bars grow from.\nBottom: up from a floor, the classic equalizer.\nTop: down from a ceiling, like icicles.\nMiddle: both ways from a centre line, like a waveform. | Try: Middle for a waveform look, Bottom for a classic equalizer.
appearance.peakHoldEnabled = Small caps that hang at each bar's recent highest point, then fall. | Try: On with a bright cap colour for a classic hi-fi look.
appearance.peakHoldColor = The colour of the peak caps. Always used, whatever the Color Mode. | Try: #15FFA2 for neon caps over red bars.
appearance.beatFlashEnabled = Briefly flashes the bars toward the Beat Flash Color on every bass hit. | Try: On to make kicks pop.
appearance.beatFlashColor = The colour bars flash toward on a beat. Lower its alpha for a gentler tint. | Try: #15FFA2 for a green pulse, #80FFFFFF for a soft white one.
appearance.beatFlashIntensity = How fast and strongly a beat reaches the flash colour. | Try: 80 for a clear flash, 150 for a punchy strobe.
appearance.rainbowSpeed = How fast the colours cycle with Color Mode set to Rainbow. | Try: 20 for a slow drift, 80 for a fast party cycle.
appearance.nowPlayingEnabled = Shows the song's artist and title near the visualizer. | Try: On with a pixel font for a retro display.
appearance.nowPlayingColor = The colour of the song title text. | Try: your palette red #E57474.
appearance.nowPlayingFont = The font for the song text (any installed font). | Try: a pixel font like Delicatus, or Segoe UI for clean text.
appearance.nowPlayingFontSize = The size of the song text, in points. | Try: 14 for a subtle label, 20 for a headline.
appearance.nowPlayingDisplaySeconds = How long the song text stays after a track changes. 0 keeps it on all the time. | Try: 0 for an always-on widget, 6 for a brief pop-up.
appearance.nowPlayingOffsetX = Slides the song text left (negative) or right, in pixels. | Try: small steps like 10 to clear the panel edge.
appearance.nowPlayingOffsetY = Slides the song text up (negative) or down, in pixels. | Try: -4 to give it a little more room above the bars.
appearance.nowPlayingBgColor = A small panel just behind the song text, so it reads over a busy wallpaper. Transparent means none. | Try: #141B1E for a dark label box.
appearance.nowPlayingBgPadding = The space between the song text and the edge of its panel. | Try: 4 for a snug box, 8 for a roomy one.
appearance.nowPlayingBgCornerRadius = How round the song text panel's corners are. | Try: 0 for square, 6 for soft.
appearance.nowPlayingBgBorderSize = An outline around the song text panel. 0 is none. | Try: 1 with your accent colour for a framed label.
appearance.nowPlayingBgBorderColor = The colour of the song text panel's outline. | Try: #64AA89 for a muted green frame.
appearance.peakFreqOffsetX = Slides the readout left (negative) or right, in pixels. | Try: small steps like 6 for fine placement.
appearance.peakFreqOffsetY = Slides the readout up (negative) or down, in pixels. | Try: -2 to lift it off the bars.
appearance.peakFreqBgColor = A small panel just behind the readout so it reads over the bars. Transparent means none. | Try: #141B1E for a dark tag.
appearance.peakFreqBgPadding = The space between the readout and the edge of its panel. | Try: 4.
appearance.peakFreqBgCornerRadius = How round the readout panel's corners are. | Try: 0 for square, 6 for soft.
appearance.peakFreqBgBorderSize = An outline around the readout panel. 0 is none. | Try: 1 for a framed tag.
appearance.peakFreqBgBorderColor = The colour of the readout panel's outline. | Try: #64AA89.
appearance.nowPlayingLayout = How the song text is laid out.\nOne line: "Artist - Title".\nTwo lines: the title, with the artist under it in its own colour. | Try: Two lines for a media-card feel.
appearance.nowPlayingPlacement = Where the song text goes.\nAbove the visualizer: over the panel, outside it.\nInside the panel, top: in the panel's padding above the bars.\nInside the panel, bottom: in the padding below them (give the panel enough padding on that side). | Try: Inside the panel, top, with 20 top padding for a tidy widget.
appearance.nowPlayingAlign = Lines the song text up on the left, in the centre, or on the right of the bars. | Try: Left to line it up with the first bar.
appearance.nowPlayingArtistColor = The colour of the artist part of the song text. | Try: #64AA89 to set the artist apart from the title.
appearance.textRendering = How the song text, readout and Terminal text are drawn.\nSmooth: soft, antialiased edges; right for normal fonts.\nPixel: hard pixels with no smoothing; right for pixel fonts at their design size (or a multiple). | Try: Pixel with a pixel font for crisp retro text.
audio.source = What the visualizer listens to.\nDefault output: what you hear, from your speakers or headphones.\nDefault input: your microphone or line-in.\nA device by name: any output or input, virtual cables included, named in Device Name. | Try: Default output to follow your music.
audio.deviceName = Part of a device's name to listen to, when Audio Source is a named device. | Try: "CABLE Output" for a virtual cable.
progress.enabled = A thin bar showing how far into the song you are, near the visualizer. | Try: On with Height 2 for a subtle progress line.
progress.placement = Where the song progress bar sits.\nBelow the panel: under the visualizer.\nAbove the panel: over it.\nInside the panel, under the bars: in the panel's bottom padding. | Try: Inside the panel for a built-in look.
progress.height = How thick the progress bar is, in pixels. | Try: 2 for a hairline, 4 for a clear bar.
progress.gap = The space between the progress bar and the panel (or the bars). | Try: 3.
progress.color = The colour of the played part of the progress bar. | Try: #64AA89 for muted green.

progress.seekAppsMode = How the Seek Apps list is used.\nExcept: click-to-seek works unless one of those apps is running (list your games).\nOnly: click-to-seek works only while one of them is running. | Try: Except, listing your games, so a click in a game never skips your song.
progress.seekApps = App names where click-to-seek is turned off (or only on), separated by commas. | Try: "obs64, League of Legends".
terminal.style = The look of the Terminal shape.\nColumns: each bar as a column of characters.\nWaterfall: a scrolling spectrum in characters, newest line on top.\nMeters: Bass, Mid, Treble and Volume as text meters. | Try: Waterfall for a hacker-screen look.
terminal.font = The font for the Terminal shape (a fixed-width one). | Try: Scientifica or Cascadia Mono.
terminal.fontSize = The text size of the Terminal shape, which sets the size of its whole grid. | Try: 12 for a dense grid.
terminal.rows = How many text lines tall the Terminal columns or waterfall are. | Try: 16 for a short block, 80 for a tall wall.
terminal.meterColumns = How many characters wide the Terminal meters are. | Try: 40.
terminal.hotThreshold = How high (as a percentage) a character has to be to turn the Hot Color. | Try: 75 for only the peaks to light up.
terminal.columnGlyph = The character the Terminal columns are built from. | Try: a full block for solid columns, # for classic text.
terminal.peakGlyph = The character used for peak caps in Terminal columns. | Try: - or _.
terminal.ramp = The characters from quiet to loud for the Terminal waterfall. | Try: " .:-=+*#%@" for classic ASCII shading.
terminal.scrollRate = How many lines per second the Terminal waterfall scrolls. | Try: 7 for slow, 20 for lively.
terminal.lowColor = The main text colour of the Terminal shape. | Try: #64AA89 for muted green.

analysis.engine = How the sound is measured.\nPrecision: every bar gets its own true band, sharp bass and fast treble; everything else in Analysis applies.\nClassic: the old 1.4 way, 7 bands the bars blend between; softer, blobbier movement. | Try: Precision.
analysis.bandLayout = How the spectrum is cut into bars.\nFrequency Scale: Bar Count bars spread over Min to Max Frequency on the Frequency Scale.\nIEC 61260: the standard audio-analyzer bands (width set by Octave Fraction); Bar Count is ignored.\nMusical notes: one bar per note, tuned to A4; Bar Count is ignored. | Try: Musical with 1/12 for a piano-like spectrum.
analysis.octaveFraction = How wide each band is for the IEC and Musical layouts; narrower means more, thinner bars.\n1/1: one bar per octave, about 10 bars.\n1/3: the classic studio analyzer, about 30 bars.\n1/6: about 60 bars.\n1/12: one bar per semitone (musical note).\n1/24: a quarter tone, about 240 bars. | Try: 1/3 for a studio look, 1/12 for notes.
analysis.minFrequency = The lowest pitch the visualizer shows (left end). | Try: 20 for deep bass, 40 to drop the rumble.
analysis.maxFrequency = The highest pitch the visualizer shows (right end). | Try: 16000 to drop empty treble bars.
analysis.tuningA4 = The reference pitch for the Musical layout. | Try: 440, the standard.
analysis.weighting = Reshapes the levels like human hearing.\nZ: flat, the honest signal.\nA: like the ear at quiet volume; pulls the bass way down, so mids and highs dominate.\nC: like the ear at loud volume; only trims the deepest bass and highest treble. | Try: Z for an honest view, A for a treble-forward look.
analysis.tilt = Tips the spectrum up toward the treble (dB per octave), because music naturally gets quieter higher up.\n0: pink noise reads flat; real music slopes down.\n1.5: a typical modern mix looks level.\n3 to 6: the treble lifted more and more, so hi-hats and air show strongly. | Try: 1.5 for level-looking music, 3 if the right side looks dead.
analysis.detector = What each bar measures in its band.\nRMS: the total energy of everything in the band; right for music.\nPeak: only the band's loudest single pitch; jumpier, closer to how a pure tone measures. | Try: RMS for music.
analysis.levelReference = How bar heights are scaled.\nThird-octave: every band compared as if it were a standard 1/3-octave band, so heights stay the same when you change Bar Count or layout.\nBand: each band's real power, so wide bars read taller than narrow ones. | Try: Third-octave.
analysis.window = A filter that decides how sharp or clean the bars look (the FFT window).\nHann: the all-round choice.\nHamming: slightly sharper peaks, a little more smearing.\nBlackman-Harris: quiet details stay visible next to loud ones; peaks slightly wider.\nFlat-top: exact loudness of pure tones, but blurry. | Try: Blackman-Harris for clean, separated peaks.
analysis.bassDetail = How much extra detail is measured in the bass (extra measuring passes).\nHigh: 3 passes; bass bars are real and separate, even at 1/12 or 1/24 octave.\nStandard: 2 passes; good for most.\nOff: one pass, like the classic engine; bass bars blur together. | Try: High for crisp bass bars.
analysis.channel = Which part of the stereo sound is shown.\nMix: both channels together.\nLeft or Right: one channel only.\nMid: what both speakers share (vocals, bass, kick).\nSide: the difference between them, showing where the stereo width is. | Try: Mix, or Side to watch the stereo width.
analysis.dbFloor = The quietest sound that still shows. Lower shows more detail, and more hiss. | Try: -72 for clean, -105 for every whisper.
analysis.dbCeiling = The level that fills a bar completely. Lower makes bars hit the top sooner. | Try: -20 for lively bars, -35 for very full ones.
analysis.ballistics = How bars rise and fall.\nSnappy: fast up and down, punchy (the old feel).\nSmooth: softer rise and fall.\nAnalyzer: falls at a steady 20 dB a second, like hardware analyzers.\nVU: slow, averaged movement like a VU meter.\nPPM EBU / PPM DIN: broadcast peak meters; jump up instantly and fall back slowly (EBU slower, DIN faster).\nCustom: uses Custom Attack and Custom Release below. | Try: Snappy for punchy, Analyzer for a calm studio fall.
analysis.attackMs = How fast bars rise with Ballistics set to Custom, in milliseconds. | Try: 10 for instant, 50 for softer.
analysis.releaseDbPerSecond = How fast bars fall with Ballistics set to Custom. | Try: 20 for steady, 60 for quick drops.
analysis.peakHoldMs = How long peak caps hang before falling, in milliseconds. | Try: 500 for a classic hang, 275 for a quicker one.
analysis.peakFall = How peak caps drop after hanging.\nGravity: they speed up as they fall, like a dropped object; the classic analyzer look.\nLinear: they fall at a steady speed. | Try: Gravity.
analysis.readout = What the readout shows.\nPeak frequency: the loudest pitch right now, in Hz.\nLoudness: how loud it is, in LUFS (momentary, short-term and integrated, the streaming standard).\nLoudness full: adds true peak, PLR (dynamics) and stereo correlation.\nBoth: frequency and loudness together. | Try: Loudness to see how loud a track is mastered.
analysis.loudnessResetOnTrack = Starts the loudness reading fresh at every new song. | Try: On to measure each song on its own.
bass.lowHz = The lowest pitch that counts as bass, for bass boost and beat detection. | Try: 20.
bass.highHz = The highest pitch that counts as bass. Higher includes kick punch, lower only deep sub. | Try: 175 to include kicks, 100 for sub-bass only.
bass.gainDb = Turns the bass bars up or down, in dB. | Try: 3 for bigger bass bars, -3 to calm them.
bass.attackPct = How fast bass bars rise compared with the rest. Under 100 is punchier. | Try: 70 for snappier kicks.
bass.releasePct = How long bass bars take to fall compared with the rest. Over 100 lets bass hang. | Try: 150 for a sustained bass look.
bass.hitSensitivity = How big a bass jump counts as a beat for Beat Flash and Particles. | Try: 65 to catch more beats, 35 for only hard kicks.
bass.hitWindowMs = How far back a beat is compared to. Short catches every bump, long only real hits. | Try: 60.
bass.lowZoneHz = Where the low colour zone ends, for multiband scope colours and the bass meter. | Try: 300.
bass.scopeFocusHz = Shows only the bass on the Oscilloscope so a bass note holds still as clean waves. 0 shows everything. | Try: 150 with a 50 ms Time Window for a bass-only scope.
bassLine.enabled = A separate thin lane that follows only the bass, with kicks and snares lighting up in their own colours. | Try: On with Placement Overlay for a bass pulse over the bars.
bassLine.style = The look of the bass lane.\nLine: a scrolling trace, like a heart monitor.\nFill: the same history as filled columns.\nBar: one live meter that flashes on kicks and snares. | Try: Line for a heartbeat trace.
bassLine.placement = Where the bass lane sits.\nBelow or Above: outside the panel.\nOverlay: inside the bars, along the bottom.\nCover: over the whole bar block, in step with the bars. | Try: Overlay to run it through the visualizer.

Behind: the bars on top. | Try: Behind with Inside the bars, so the scope runs over the lane.

bassLine.width = How wide the bass lane is. 0 matches the bars. | Try: 0.

bassLine.offsetX = Slides the bass lane left (negative) or right, in pixels. | Try: small steps like 4.
bassLine.offsetY = Slides the bass lane up (negative) or down, in pixels. | Try: small steps like -4.
bassLine.bodyColor = The colour of the bass lane itself. | Try: your palette red #E57474.

hardware.workload = Which chip does the work.\nHybrid: the processor measures the sound, the graphics card draws; cheapest on almost every PC.\nGPU: the graphics card does both; the processor only copies audio.\nCPU: the processor does everything, drawing included.\nNPU: an Intel AI chip measures the sound (experimental, rarely saves power). | Try: Hybrid.
hardware.renderDevice = Which graphics chip draws.\nAuto: the one your monitor is plugged into (best almost always).\nIntegrated: the built-in chip, lowest power.\nDiscrete: the graphics card, highest performance.\nCPU: drawn in software. | Try: Auto.
hardware.renderer = How the visualizer is drawn.\nDirect3D 11: fast, skips frames where nothing moved, and needed for glow, bloom, glass and outlines.\nDirect2D: the older 1.5 way, kept for comparison and as a fallback. | Try: Direct3D 11.
hardware.opaquePanel = With a fully solid panel (or Blur on) and Auto-Hide off, lets Windows skip blending behind it to save work.\nAuto: does that when it can.\nOff: always blends. | Try: Auto.
hardware.npuRuntimePath = Where the NPU software lives, for Workload set to NPU. | Try: leave empty.
hardware.frameSync = How frames line up with your screen's refresh.\nAuto: VSync on integrated graphics or CPU drawing, otherwise Off.\nOff: a plain timer at Target FPS, any value.\nVSync: every frame on its own refresh, capped at the refresh rate; smoothest.\nAdaptive: VSync up to the refresh rate, uncapped above.\nFast Sync: uncapped, always showing the newest frame. | Try: VSync for the smoothest motion.
hardware.lowLatency = How close to the screen's refresh each frame is drawn (with Frame Sync on); closer means bars react sooner.\nOff: half a refresh ahead, safest.\nOn: a quarter refresh ahead.\nUltra: just in time, measured on this PC; the least delay. | Try: On for snappier bars.
hardware.frameGen = Draws an in-between frame for every two real ones.\nOff: every frame measured and drawn.\nx2: the sound is measured at half the rate and halfway frames fill in; less work, one frame more delay. | Try: Off.
hardware.engineCores = Which processor cores run the visualizer.\nAuto: Windows decides.\nEfficiency: the low-power cores; least power.\nPerformance: the fast cores; steadiest timing.\nCustom: the cores listed in Custom Cores. | Try: Efficiency on a laptop, Auto otherwise.
hardware.engineCoreList = The exact processor cores to use, with Engine Cores set to Custom. | Try: leave empty.
